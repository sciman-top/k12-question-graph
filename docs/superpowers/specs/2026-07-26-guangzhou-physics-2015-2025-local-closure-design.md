# 2015-2025 广州中考物理本机闭环设计

- 日期：2026-07-26
- 状态：设计已批准，待实施计划
- 设计选择：版本化重导入并对比切换
- 当前作用域：本机 PostgreSQL、FileStore、API、Worker、Web 与浏览器工作流

## 1. 背景与当前真值

项目已经具备导入、切题、审核、题库、组卷、导出、成绩和分析的代码、数据库模型与合同门禁，但现有完成态主要证明仓库侧或代理流程存在，不能证明 2015-2025 广州中考物理真实资料已形成可复用的教师工作流。

2026-07-26 盘点结果如下：

- 新来源目录为 `D:\KQG_Data\guangzhou_physics_2015_2025`。
- 目录包含 32 份 PDF，共 71,966,156 bytes。
- 2015-2019、2021-2025 每年包含试卷、答案或解析、年报三类文件。
- 2020 包含一份试卷答案合并 PDF 和一份年报 PDF。
- 2015 试卷与答案 PDF 的 SHA-256 与既有 FileStore 原件一致，其他来源必须按新 hash 登记。
- 现有 C003 候选包有 210 道题、349 个小题、82 个知识节点、47 个考点，但这些记录仍为 `pending_review`，不能只按文件名直接投影为正式事实。
- PostgreSQL 17 在本机运行；Web 可监听 `5173`，API、本机数据库凭据与全工作流仍需在实施阶段重新启动和验证。

## 2. 目标与完成定义

本设计的目标是建立一个可重复、可审计、可恢复的本机真实资料闭环：

```text
真实 PDF
-> 来源登记与去重
-> 页面解析、渲染与 OCR 诊断
-> 切题与来源区域
-> 答案/解析关联
-> 知识点、考点、题型、能力与难度候选
-> 审核与修订
-> 题库检索
-> 智能组卷与换题/撤销
-> Word/PDF 导出
-> 成绩导入
-> 学情分析与讲评
-> 备份恢复和证据收口
```

本机闭环完成必须同时满足：

1. 32 份 PDF 均有稳定来源 ID、SHA-256、文件角色、年份、页数、解析模式和 FileStore 路径。
2. 2015-2025 每年题号、题数、答案覆盖、来源页和切题区域均有机器可读报告。
3. 每道题至少可回溯到原 PDF、页码和题目区域；异常项进入明确审核队列。
4. 知识点、广州考点、题型、能力维度和难度均带来源、状态、置信度和生成方式。
5. 教师可在真实 Web 工作台完成审核、保存、检索、组卷、导出、成绩和分析主链路。
6. 数据库、FileStore 和批次 manifest 可备份、校验、恢复并只回滚本批次。
7. 完整门禁、数据库不变量、浏览器 E2E、视觉审查和导出工件检查通过。

本机闭环不等于隔离机、学校网络、真实教师签字或最终发布验收。上述边界仍保持开放，不得由本机结果替代。

## 3. 来源与存储设计

### 3.1 版本化来源批次

新资料迁移到：

`D:\KQG_Data\source_materials\imported\guangzhou_physics_2015_2025\20260726-v2\raw`

迁移采用以下顺序：

1. 对输入目录生成不可变 inventory，包括原路径、文件名、长度、mtime、SHA-256、PDF magic、页数和文本可提取字符数。
2. 生成数据库、FileStore 与既有来源映射快照。
3. 创建版本化目标目录并移动文件。
4. 重新计算目标文件 hash，与迁移前 inventory 完全比对。
5. 只有全部匹配后才把批次标为 `staged`；不删除已存在的 FileStore 内容。

2015 的相同 hash 文件复用既有 content-addressed 原件。新来源通过现有 FileStore hash 路由写入，数据库只存 metadata、path、hash 和状态。

### 3.2 来源角色与稳定标识

每个年份建立来源组：

- `exam_paper`
- `answer_or_solution`
- `exam_year_report`

2020 的合并 PDF 同时映射 `exam_paper` 与 `answer_or_solution` 两个逻辑角色，但物理文件只存一份。来源稳定标识基于 `region + subject + year + role + content_hash`，不以易变文件名作为唯一键。

旧 C003 记录通过 `year + question_number + source evidence + content comparison` 与新批次对齐。文件名差异只进入兼容映射，不能触发覆盖式更新。

## 4. 数据处理设计

### 4.1 入库与切题

每份 PDF 先经过解析诊断，选择文本提取、版面分析、OCR 或人工接管 profile。每年处理结果至少包含：

- `FileAsset`
- `SourceDocument`
- 页级渲染图
- `CutCandidate`
- `SourceRegion`
- `QuestionItem`
- `QuestionBlock`
- `QuestionAsset`
- 答案与解析证据
- `ReviewQueueItem`

切题器必须处理题号连续性、跨页题、共用题图、表格、公式、答题区域和答案页分离。低置信度、题数不一致、页码越界、空白截图、重复区域或答案缺失均 fail-closed 到审核队列。

### 4.2 题目与答案对齐

题目主键使用稳定 question key，而不是数据库自增序号。答案关联按年份、题号、小题号和来源锚点完成，并验证：

- 每道客观题答案唯一；
- 主观题评分点可多条但顺序稳定；
- 答案证据可回看；
- 试卷与答案题数差异有显式异常；
- 2020 合并文档的试题页和答案页不会相互切入错误区域。

## 5. 知识点、考点与难度设计

### 5.1 知识体系

现有 C002 active 版本继续作为当前正式知识体系。新批次不得直接修改 active；新增或修订内容必须走 C002R 的 candidate、mapping、impact report、review、rollback snapshot 和 admin active switch 流程。

现有 82 个知识节点和 47 个广州考点先作为候选基线，逐项核对课程标准、教材、试卷和年报证据。映射支持一对一、一对多、多对一和多对多。

### 5.2 标签生成

标签按确定性优先顺序生成：

1. 文件名、年份、题号、题型、分值和显式章节等确定性字段；
2. 课程标准、教材节点、知识点和考点的规则映射；
3. AI 生成的候选知识点、考点、能力维度、难度和解析建议；
4. 审核确认、修订或退回。

所有 AI 输出保持 `candidate/pending_review/productionEligible=false`，记录模型角色、reasoning、prompt/schema 版本、token、成本、缓存、输入 hash 和输出 hash。

### 5.3 难度语义

难度来源必须区分：

- `source_reported`：年报或正式统计直接提供；
- `rule_estimated`：依据题型、步骤、知识组合和计算量估算；
- `ai_estimated`：模型候选；
- `teacher_confirmed`：人工确认。

系统不得把估计难度显示成官方实测难度。冲突时保留多来源记录和裁决审计。

## 6. 人机协作设计

自动化负责来源校验、批量解析、切题候选、标签候选、异常检测、工件生成和证据汇总。AI 负责语义候选、复杂映射和视觉复核，但不代替来源证据、审核责任或 active 切换。

审核工作台必须支持：

- 原页与切题区域并排查看；
- 题干、答案、解析、标签、难度和来源联动修改；
- 重裁、关联/解除题图、表格与公式；
- 确认、退回、修订、撤销和审计回放；
- 批量操作前预览受影响范围；
- 任一步失败后保留来源和继续路径。

自动视觉审查可覆盖全部页面和题目区域，但没有责任签字的记录不能标为教师生产审核完成。

## 7. 教师工作流与 UI 验证

API、Worker 和 Web 启动后，使用真实批次执行：

1. 上传或选择来源试卷；
2. 查看解析和切题进度；
3. 修正异常题并确认标签；
4. 保存后从来源回看；
5. 按知识点、考点、题型、年份和难度检索；
6. 通过筛选和自然语言建立题篮；
7. 审核蓝图，换题并撤销；
8. 导出 Word/PDF 并打开检查；
9. 使用 synthetic/anonymized Excel 导入成绩；
10. 生成确定性分析和 draft 讲评报告。

浏览器验证同时检查功能、网络请求、控制台错误、加载/空白/失败状态、键盘与焦点、文字溢出、遮挡、响应式布局和管理员/教师权限边界。关键页面保留桌面与移动截图；来源截图、题卡和导出工件做像素级非空与可读性检查。

## 8. 错误处理与回滚

任何写入前必须存在通过校验的数据库备份、FileStore manifest 和恢复命令。外部文件/证据使用 `sourceBatchId=guangzhou-physics-2015-2025-20260726-v2`；数据库遵循既有 token normalization，使用等价的 `material_batch_key=guangzhou_physics_2015_2025_20260726_v2`，报告必须显式记录二者映射。

失败处理规则：

- 文件移动 hash 不一致：立即停止，保留源和目标，不进入数据库；
- PDF 无法解析：切换 OCR profile，仍失败则进入人工接管；
- 题数或答案数不一致：该年份不得进入 reviewed 状态；
- 数据库写入失败：事务回滚，FileStore 未引用对象进入可审计清理清单；
- AI/外部服务失败：回退确定性路径或人工队列，不伪装成功；
- UI/E2E 失败：保留日志、截图、请求响应和最小复现；
- 回滚只删除或恢复本批次对象，不用 Git 回滚替代数据恢复。

5. 答案、解析、题图、表格和公式关联；
6. 知识点、考点、难度和能力标签；
7. 审核工作台与 API 数据闭环；
8. 检索、智能组卷、导出、成绩和分析；

每个切片必须有验收标准、验证命令、证据路径和仅回滚该切片的入口。发现代码缺口时只修复当前纵向工作流所需边界，不扩张到隔离机、学校网络、多学科或高级平台能力。
